# P0: 画面冒頭の情報設計と操作説明 実装仕様

## 1. 目的

トップページを開いた人が、画面の目的、年齢・性別の変更が画面に与える影響、タイムラインの見方をすぐ理解できるようにする。新しい機能を追加するのではなく、既存機能の説明と配置を整理する。

## 2. 現状

- `src/app/page.tsx` がメイン領域に `LifeTimeline` と `LifeEventTable` を順に配置する。
- `src/app/components/LifeTimeline.tsx` が「人生タイムライン」の見出しと性別選択欄を表示する。
- `src/app/components/Timeline.tsx` が現在年齢の入力、イベント／目標の凡例、年齢位置へ移動するボタン、タイムライン、人生の進行度を表示する。
- 性別は `LifeTimeline`、現在年齢の入力値と表示値は `Timeline` が状態を管理する。どちらの変更も保存されず、ページを再表示すると設定CSVの初期値に戻る。
- 画面の目的や年齢・性別の変更が保存されないことを、操作前に説明する導入文はない。

## 3. 目標と画面構成

トップページの情報を次の順に配置する。

1. ページ見出し「人生タイムライン」
2. 画面の目的を伝える短い導入文
3. 年齢と性別をまとめた「表示条件」
4. 表示条件が保存されないことの注記
5. タイムラインと操作・凡例の案内
6. 人生の進行度
7. データ一覧

主要コンテンツの順序は「人生タイムライン」→「人生の進行度」→「データ一覧」を維持する。導入文や注記によって、既存機能を画面下へ押し下げすぎないよう簡潔にする。

### 3.1 導入文

次の文言を基本案とする。実装時に意味を変えず、より短い表現へ調整してよい。

> 人生の出来事や目標を年齢軸で確認できます。年齢や性別を変えると、タイムラインと進行度の表示がその場で切り替わります。

### 3.2 表示条件

- 現在年齢と性別を、見出しまたは `fieldset` の `legend` が「表示条件」となる一つの視覚的なグループにまとめる。
- 現在年齢は整数0〜100歳、性別は既存の選択肢を使う。各コントロールのラベルと入力方法は維持する。
- 現在年齢の変更はタイムライン上の現在位置と経過状態、人生の進行度に反映する。
- 性別の変更は平均寿命・健康寿命の目安と人生の進行度に反映する。
- 次の注記を表示条件の近くに置く。

> 年齢と性別の変更はこの画面だけに反映され、保存されません。ページを再表示すると設定CSVの値に戻ります。

現在年齢の入力値と表示値は現在 `Timeline` が管理し、性別は `LifeTimeline` が管理している。両方を同じグループに配置するため状態を移動する場合は、現在年齢の入力途中値、不正値の確定時処理、年齢変更後の表示更新を維持する。状態の配置を変えても設定CSVへ書き込まない。

### 3.3 タイムラインの案内

- 年齢軸は0〜100歳で、横スクロールして閲覧できることをタイムラインの近くで案内する。
- イベントは丸、目標はひし形で示すことを既存の凡例で説明する。
- 現在年齢までの項目とこれからの項目の表示差は、色だけに依存せず短いラベルまたは形状以外の視覚的な差で説明する。
- 既存の年齢位置への移動ボタン、マーカー選択、詳細表示の操作は維持する。案内表示が操作領域やマーカーを覆わないようにする。

## 4. レスポンシブ・アクセシビリティ要件

- PCでは表示条件を一まとまりとして見せ、タイムラインや寿命の凡例との区別を明確にする。
- 狭い画面では表示条件と案内を縦に折り返し、横スクロール領域を画面幅からはみ出させない。
- 見出し階層を崩さず、年齢・性別の各入力に明示的なラベルを付ける。視覚上のグループ名はスクリーンリーダーでも認識できるようにする。
- すべての入力とボタンをキーボードで操作でき、フォーカス表示を維持する。
- 既存のライト／ダークモード配色を変更しない。案内を色だけで区別しない。

## 5. 実装対象

- `src/app/components/LifeTimeline.tsx`: ページ見出し、導入文、性別入力、表示条件のグループ化と非保存の注記。
- `src/app/components/Timeline.tsx`: 現在年齢入力の配置または状態受け渡し、タイムラインの操作案内。年齢位置・凡例・寿命目安・進行度の計算は維持する。
- `src/app/page.tsx`: 必要な場合のみ構成を調整する。データ読込とエラー表示の挙動は変更しない。
- `__tests__/src/app/page.test.tsx`: 導入文、表示条件、非保存の注記と既存の性別・進行度動作を確認する。
- `__tests__/src/app/components/Timeline.test.tsx`: 現在年齢変更、タイムライン移動、凡例・案内の表示と既存操作を確認する。

## 6. 受け入れ条件

- 初めて画面を開いた人が、タイムラインの目的と年齢・性別を変更した際の反映先を導入文から理解できる。
- 現在年齢と性別が一つの「表示条件」として認識でき、それぞれの入力ラベルも分かる。
- 年齢・性別の変更が保存されないことと、再表示時に設定CSVの値へ戻ることが明示されている。
- 年齢変更はタイムラインと進行度に、性別変更は寿命目安と進行度に反映される。
- タイムラインの横スクロール、年齢位置への移動、マーカー選択、データ一覧の既存動作を損なわない。
- PCと幅320 CSS px相当の画面で、表示条件、案内、操作部品が重ならず利用できる。
- ライト／ダーク両テーマで文字と操作対象を識別でき、既存の配色を変更しない。

## 7. 対象外

- 年齢・性別設定の保存、アカウント機能、データ編集などの新機能。
- 平均寿命・健康寿命の値や定義、進行度計算、年齢0〜100歳の時間軸の変更。
- タイムライン上の項目順・位置、イベント／目標マーカーの形状、既存テーマ配色の変更。
- 寿命目安そのものの説明や統計上の注意の見直し。これは別のP0提案として扱う。

## 8. 検証

自動テストでは導入文・入力グループ・非保存の注記と、年齢・性別変更時の表示更新を確認する。実装後は次のコマンドを実行する。

```text
npm test -- --runInBand __tests__/src/app/page.test.tsx __tests__/src/app/components/Timeline.test.tsx
npm run lint
```

ブラウザーではデスクトップと幅320 CSS px相当で表示・操作を確認し、ライト／ダーク両テーマで案内と入力グループの視認性を確認する。

# デザイナー視点のUI/UX改善提案

## 1. 目的と前提

本書は、人生タイムライン、人生の進行度、データ一覧を備えた現行画面を、初めて訪れた人にも理解しやすく、PC・スマートフォン・キーボード操作のいずれでも扱いやすくするための改善案である。以下はデザイン提案であり、既存要件や確定済みの仕様を変更する決定ではない。

### 現状の画面と仕様

- トップページに年齢・性別の入力、0〜100歳の横スクロール式タイムライン、平均寿命・健康寿命の目安、進行度、絞り込み可能なデータ一覧が並ぶ。
- タイムラインは固定幅で、項目はマーカーの形と経過済み／これからの塗り分けで表現される。マーカーにホバーまたはフォーカスすると概要を表示し、選択すると説明を表示する。
- 年齢と性別の変更は表示に反映されるが、設定CSVには保存されず、再読み込みすると初期値に戻る。
- データ一覧は複数条件で絞り込み・並べ替えできる。スマートフォンでは横スクロールが必要な表である。
- 初期版ではデータの追加・編集を行わない。ダークモードの既存配色は変更しない。

## 2. デザイン上の課題

1. **最初に見るべき情報が多い。** 時間軸、寿命の統計値、進行度、検索・絞り込みが同じ画面に続くため、初見では「まず何を見ればよいか」が伝わりにくい。
2. **スクロール操作に気づきにくい。** 時間軸と表の両方に横スクロールがあり、特にタッチ端末では画面全体の縦スクロールと混同しやすい。
3. **入力値の意味が曖昧になりやすい。** 年齢・性別の変更が保存されないことや、統計上の目安が個人の寿命予測ではないことは、操作の近くで説明する必要がある。
4. **項目が密集する場合に読み取りづらい。** マーカーが増えると縦方向の情報量が増え、概要カードが重なり合う項目の確認を妨げる可能性がある。
5. **モバイルで一覧の比較が難しい。** 6列の表を横に移動しながら読む必要があり、項目間の比較やフィルター結果との往復に負荷がかかる。

## 3. 改善案と優先度

影響度は、利用者が目的を理解し、必要な情報へ到達するまでの負担を基準とする。工数はデザイン・実装の相対的な目安であり、技術調査後に見積もる。

| 優先度 | 改善案 | 期待する効果 | 目安 |
| --- | --- | --- | --- |
| P0 | 画面冒頭の情報設計と操作説明を整理する | 最初の理解を助け、設定変更に伴う誤解を減らす | 小 |
| P0 | 寿命目安の説明と統計上の注意を近接表示する | 数値を個人の予測と誤認するリスクを抑える | 小 |
| P1 | タイムラインの横スクロールと密集マーカーを改善する | イベントの探索・選択をしやすくする | 中 |
| P1 | データ一覧の絞り込み状態と結果を明確にする | 条件の把握・解除・再探索を容易にする | 小〜中 |
| P1 | モバイルの一覧閲覧を最適化する | 横スクロールによる読み取り負荷を軽減する | 中〜大 |
| P2 | キーボード・スクリーンリーダー操作を通して確認する | 利用者や入力方法に依存しない操作性を高める | 中 |

### P0: 画面冒頭の情報設計と操作説明

- ページ冒頭に短い説明を置き、「人生の出来事と目標を年齢軸で眺める画面」であることを伝える。
- 現在年齢と性別をひとまとまりの「表示条件」として見せ、変更がその場の表示にだけ反映される旨を入力欄の近くに記す。保存されるプロフィール設定と誤認させない。
- 主要コンテンツは「人生タイムライン」→「人生の進行度」→「データ一覧」の順に見出しと余白でグルーピングする。新しい主要機能を追加するのではなく、既存コンテンツの優先順位を明確にする。
- タイムラインの凡例は線種・形・塗り分けを短いラベルで説明し、見た目だけに意味を依存させない。
- モバイルでは、横に動かせる領域の端に続きがあることを示す視覚的な手がかりと、「左右にスクロールできます」の案内を配置する。操作を妨げる常時表示のオーバーレイは避ける。

### P0: 寿命目安の伝え方

- 「平均寿命」「健康寿命」は日本の統計上の参考値であり、個人の寿命や健康状態の予測ではないことを、凡例または進行度の説明からすぐ確認できるようにする。
- 指標の対象（日本）、データ年、性別区分、値をひとまとまりで提示する。詳細な出典は補足リンクや折りたたみ説明へまとめ、主画面の読みやすさを保つ。
- 統計値を強い警告色やカウントダウン風の表現で強調しない。既存の色使いを維持し、色に加えてラベル・線種・数値でも区別する。
- 100%を超える表示は仕様どおり維持し、「目安に対する割合」であることを明記して、上限超過をエラーや警告のように見せない。

### P1: タイムラインの探索・選択

- 目盛り、現在年齢、平均寿命・健康寿命の参照線、イベントマーカーの見た目とラベルを整理し、現在位置と統計上の目安をすばやく見分けられるようにする。
- 項目を選択した後の説明領域を安定した詳細パネルとして扱い、選択中の項目名・年齢・カテゴリ・目標状態を一緒に表示する。パネルの閉じ方と選択状態も分かるようにする。
- 同じ年齢付近に項目が集まるケースを代表データで確認する。カードが隣接するカードや画面端に重なる場合は、表示位置の調整または選択中カードの前面表示を検討する。
- モバイルでは年齢軸全体を維持する前提で、横スクロール領域と項目カードのタップ領域を分かりやすくする。スクロール中に意図しない項目選択が起こらないことも確認する。
- 入力年齢を動かすとタイムラインと進行度が変わることを、入力欄付近の短い説明で示す。シミュレーション用の年齢操作と保存プロフィールの編集は区別し、保存機能を追加する場合は別途仕様決定する。

### P1: データ一覧の絞り込みとモバイル表示

- 絞り込み条件を「キーワード」「種別」「カテゴリ」「目標状態」として視覚的にまとまりよく配置し、適用中の条件と件数を一覧の近くに示す。
- 条件適用後は、現在の条件を一目で確認できる表示と「条件をクリア」操作を維持・強調する。該当なしの場合は空である理由が条件によるものと分かる案内を出す。
- 並べ替え中の列と昇順・降順は、列見出しのアイコンだけでなくアクセシブルな状態情報でも伝える。
- モバイルでは、列を横スクロールする現行方式を保つか、カード型の項目一覧へ切り替えるかを比較検討する。カード化する場合も、全項目・並べ替え・絞り込み・ページ送りの機能を損なわず、情報の優先順位を決めてから採用する。
- 表示件数・ページ位置・絞り込み結果を、検索条件を変えた後も一貫した位置と文言で確認できるようにする。

### P2: アクセシビリティと状態表示

- キーボードのみで、ヘッダー、入力欄、タイムライン項目の選択、フィルター、ソート、ページ移動を一通り操作できるか確認する。
- フォーカス位置が常に見えること、ツールチップや詳細表示がキーボード利用時にも参照・終了できることを確認する。
- 読み上げ順が視覚的な情報順と一致するよう、見出し階層、フォームラベル、状態通知を確認する。件数や並べ替え結果など、操作で変化する情報は必要な範囲で通知する。
- 色だけで情報を区別しない。既存のマーカー形状・テキスト・線種による表現を維持し、ライト／ダーク両テーマでコントラストを確認する。
- 動きのある表示は、OSの「視差効果を減らす」設定を尊重し、操作や情報取得に必須としない。

## 4. 推奨する進め方

1. **小さく整える:** ページ冒頭の説明、入力値の非保存に関する注記、統計の注意書き、凡例、横スクロール案内を追加・整理する。
2. **実データで試す:** 項目が少ない場合・同じ年齢に集中する場合・説明が長い場合のタイムラインと、狭い画面での一覧を確認する。
3. **モバイル一覧を決める:** 横スクロール表とカード型表示を、主要タスク（項目の検索、年齢・状態の確認、詳細比較）で比較し、実装方式を選択する。
4. **アクセシビリティを検証する:** キーボード操作、スクリーンリーダー、拡大表示、ライト／ダークモードで主要タスクを確認する。

表示モードの永続化、データ編集、寿命目安の仕様変更など、利用者の期待や要件を変える提案は本書だけで確定しない。実装前にプロダクト仕様として判断する。

## 5. 効果の確認方法

変更前後で同じタスクを試し、少数の利用者による観察と定量値の両方で確認する。具体的な目標値は、現状値を計測してから設定する。

- 初見の利用者が、タイムラインの見方と年齢・性別の変更範囲を正しく説明できるか。
- 指定したイベント・目標を検索し、年齢・カテゴリ・状態・説明を確認できるか。
- スマートフォンで横スクロール領域に気づき、目的の項目まで到達できるか。
- 絞り込み後の件数、適用中の条件、条件解除方法を迷わず把握できるか。
- キーボードのみで主要タスクを完了できるか。操作不能箇所や見失うフォーカスがないか。
- タスク完了率、完了までの時間、誤操作・行き戻り、利用者の理解度と主観的な負担を記録する。

## 6. 対象外・要確認事項

- CSVの追加・編集、設定値の保存、ログインなどの新機能は対象外。
- ダークモードの既存配色、寿命データの値・定義、年齢0〜100歳の時間軸、CSV由来のデータ表示要件は変更しない。
- モバイル一覧をカード型へ切り替えること、現在年齢の入力をどのような用途として見せるかは、ユーザーテストやプロダクト判断を経て決定する。

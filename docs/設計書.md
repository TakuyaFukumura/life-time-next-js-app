# 人生可視化アプリ 設計書

## 1. 文書の目的

本書は [`要件定義書.md`](./要件定義書.md) に記載された初期要件を、画面・データ・既存アプリ構成の設計へ落とし込むための文書である。

要件として確定している内容と、これから決める設計内容を区別する。未決定の設計事項は「検討事項」に一問一答形式で記録し、回答を受けて順次確定する。

## 2. 設計の前提

### 2.1 要件から引き継ぐ制約

- 主な利用者は、自分自身の人生を記録・計画する個人利用者とする。
- 年齢を横軸とし、0歳から100歳までの時間軸上にイベントや目標を表示する。
- 項目には名称・年齢・カテゴリ・説明を持たせる。目標には未着手・進行中・達成・中止の状態を持たせる。
- 初期カテゴリは「仕事」「家族」とする。
- 初期版ではカテゴリ別横棒グラフを表示せず、人生の時間軸を中心に構成する。
- 初期データはリポジトリ内のCSVから読み込み、画面からの追加・編集は行わない。
- CSVに不正な行または必須項目の欠落がある場合、エラーを表示し、データを表示しない。
- PCとスマートフォンの両方に対応し、画面表示は日本語とする。
- 既存のダークモード切替を残し、切替時の配色は変更しない。

### 2.2 現行アプリの技術的な前提

- Next.js App Router、React、TypeScript、Tailwind CSSを使用している。
- `src/app/page.tsx` は現在、テンプレート由来のメッセージ表示を担当している。
- `src/app/layout.tsx` は共通レイアウトと `DarkModeProvider`、`Header` を組み込んでいる。
- `DarkModeProvider` と `src/app/globals.css` がダークモードの状態管理と配色を担っている。
- テンプレート由来のメッセージAPIやSQLite機能は、人生可視化機能に不要であれば置き換え・削除できる。ダークモード機能は維持する。

## 3. 画面構成案

以下は要件から導いた論理的な構成案であり、配置・寸法・操作方法は未確定とする。

1. **共通ヘッダー**: アプリ名と既存のダークモード切替を表示する。
2. **人生タイムライン**: 0歳から100歳までの横方向の時間軸を表示する。
3. **タイムライン項目**: イベントと目標を時間軸上に配置し、名称・年齢・カテゴリ・説明を示す。目標には達成状態も関連付ける。
4. **読み込み状態**: CSVの読み込み中、正常表示、読み込み・検証エラーの各状態を扱う。

初期版ではカテゴリごとの横棒グラフや画面上でのデータ編集を設けない。項目の詳細表示方法、目盛り、項目が重なる場合の配置などは検討事項とする。

## 4. データの流れ案

`data/life-events.csv` を入力元とし、データの読み込み・解析・検証を経て、検証済みの項目をタイムラインへ渡す流れを想定する。読み込み処理をサーバー側とクライアント側のどちらに置くかは別途決定する。

```text
data/life-events.csv
    ↓
読み込み・解析・必須項目の検証
    ├─ 正常: 検証済みデータをタイムラインに表示
    └─ 異常: エラーを表示し、データは表示しない
```

CSVの列定義・文字コード・解析方法、読み込み処理をサーバー側とクライアント側のどちらに置くかは未決定であり、本書の検討事項とする。

## 5. データ項目案

| 項目 | 要件上の用途 | 設計上の検討 |
| --- | --- | --- |
| 種別 | イベントと目標を区別する | CSV上での表現方法 |
| 名称 | 項目の識別・表示 | 空欄を許容するか |
| 年齢 | 時間軸上の位置 | 整数・小数、0〜100の境界の扱い |
| カテゴリ | 仕事・家族の分類 | 値の表現、未知カテゴリの扱い |
| 説明 | 項目の補足情報 | 表示場所、空欄を許容するか |
| 目標状態 | 目標の進捗 | イベントでは値を持たない場合の扱い |

この表は検討用の論点整理であり、CSVの列名・必須条件・型・保存形式を確定するものではない。

## 6. 既存機能との関係

- 共通レイアウトおよびダークモード切替は維持する。
- ダークモードの配色定義を変更せず、新しい画面要素は既存の配色との整合を設計時に確認する。
- テンプレート由来のメッセージ表示、メッセージAPI、SQLite連携は、初期要件に不要な範囲で置き換え・削除の対象とする。
- 実装時に削除するファイル、コンポーネント、テストの具体的な範囲はコード変更前に確認する。

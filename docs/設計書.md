# 人生可視化アプリ 設計書

## 1. 文書の目的

本書は [`要件定義書.md`](./要件定義書.md) に記載された初期要件を、画面・データ・既存アプリ構成の設計へ落とし込むための文書である。

要件として確定している内容と、これから決める設計内容を区別する。未決定の設計事項は「検討事項」に一問一答形式で記録し、回答を受けて順次確定する。

## 2. 設計の前提

### 2.1 要件から引き継ぐ制約

- 主な利用者は、自分自身の人生を記録・計画する個人利用者とする。
- 年齢を横軸とし、0歳から100歳までの時間軸上にイベントや目標を表示する。
- 現在年齢は `data/life-settings.csv` から整数で読み込む。初期サンプル値は29歳とし、設定CSVがない、または0〜100歳以外の値は不正として扱う。
- 性別は `data/life-settings.csv` から読み込む。値は「男性」「女性」「その他」「未設定」とし、サンプルCSVは「男性」、性別欄が空の場合は「未設定」とする。トップページのプロフィールに表示する。
- 平均寿命は厚生労働省の2025年簡易生命表を使い、男性81.35歳、女性87.33歳をタイムライン上の破線で示す。「その他」「未設定」は男女平均84.34歳とする。
- 時間軸の現在年齢までを濃い線、それ以降を薄い線で示し、境界に「現在」と年齢を表示する。
- 項目には名称・年齢・カテゴリ・説明を持たせる。目標には未着手・進行中・達成・中止の状態を持たせる。
- 初期カテゴリは「仕事」「家族」「学業」とする。
- 初期版ではカテゴリ別横棒グラフを表示せず、人生の時間軸を中心に構成する。
- 初期データはリポジトリ内のCSVから読み込み、画面からの追加・編集は行わない。
- CSVに不正な行または必須項目の欠落がある場合、エラーを表示し、データを表示しない。
- PCとスマートフォンの両方に対応し、画面表示は日本語とする。
- 既存のダークモード切替を残し、切替時の配色は変更しない。

### 2.2 現行アプリの技術的な前提

- Next.js App Router、React、TypeScript、Tailwind CSSを使用している。
- `src/app/page.tsx` はサーバー側でイベントCSVとプロフィール設定CSVの読込・検証を呼び出し、正常時に検証済みイベントと現在年齢を `src/app/components/Timeline.tsx` へ渡し、性別をプロフィールとして表示する。
- `src/app/components/Timeline.tsx` はクライアントコンポーネントとして項目を表示し、選択された項目の説明を表示する。
- `src/app/layout.tsx` は共通レイアウトと `DarkModeProvider`、`Header` を組み込んでいる。
- `DarkModeProvider` と `src/app/globals.css` がダークモードの状態管理と配色を担っている。
- テンプレート由来のメッセージAPIやSQLite機能は削除し、ダークモード機能は維持する。

## 3. 画面構成

1. **共通ヘッダー**: 既存どおり左側にアプリ名、右側にダークモード切替を配置する。
2. **プロフィール**: メインページ上部に設定CSVから読み込んだ性別を表示する。
3. **人生タイムライン**: サーバー側で読み込み・検証したイベントと現在年齢を専用の表示コンポーネントに渡し、0歳から100歳までの横方向の時間軸を10年ごとの目盛りで表示する。現在年齢までを濃い線、それ以降を薄い線で示し、境界に「現在」と年齢を表示する。性別に応じた日本の平均寿命の目安を色付き破線と凡例で示す。タイムライン全体は固定幅とし、スマートフォンでは横スクロールで閲覧する。
4. **タイムライン項目**: イベントは丸、目標はひし形のマーカーで示す。年齢が現在年齢以下のマーカーは塗りつぶし、現在年齢より先のマーカーは枠線のみで表示する。同じ年齢や重なりやすい年齢の項目は年齢位置を保ち、縦方向にずらして並べる。初期表示ではカードを隠し、マーカーへのホバー・キーボードフォーカス・タップで名称・年齢・カテゴリを含むカードを浮かび上がらせる。目標には状態名も表示する。カテゴリと状態は色を変えずテキストで示す。マーカーを選択すると説明を表示し、再選択すると閉じる。
5. **読み込み状態**: CSV読み込み中はローディング表示を行う。イベントCSVとプロフィール設定CSVの両方が正常な場合に検証済みデータを表示する。いずれかのCSVを読み込めない場合、または不正なデータがある場合は「サンプルデータを読み込めませんでした」と表示し、データは表示しない。データが0件の場合は空の状態を表示する。
6. **登録データ一覧**: タイムラインの下にCSVの全項目を年齢順の表形式で表示する。種別・名称・年齢・カテゴリ・説明・目標状態を列として含め、イベントや任意の説明に値がない場合は「—」を表示する。各列のヘッダーから昇順・降順にソートでき、初期状態は年齢の昇順とする。別の列を選ぶと昇順でソートし、同じ列を再度選ぶと順序を反転する。種別・カテゴリ・目標状態を選択し、名称・説明のキーワードで絞り込める。条件はANDで適用し、条件またはソートの変更時は1ページ目に戻る。一致するデータがない場合は空の状態を表示する。1ページ10件とし、「前へ」「次へ」でページを移動できる。現在の表示範囲と絞り込み後の件数を表示する。スマートフォンでは表を横スクロールで閲覧する。

初期版ではカテゴリごとの横棒グラフや画面上でのデータ編集を設けない。

## 4. データの流れ案

`data/life-events.csv` と `data/life-settings.csv` をNext.jsのサーバー側で読み込み、`csv-parse`で解析・検証したイベントとプロフィール設定を画面へ渡す流れとする。

```text
data/life-events.csv ─┐
                      ├─ サーバー側で読み込み・解析・検証
data/life-settings.csv┘
    ↓
`csv-parse`による解析・必須項目の検証
    ├─ 正常: 検証済みイベントと現在年齢をタイムラインと登録データ一覧に、性別をプロフィールに表示
    └─ 異常: エラーを表示し、データは表示しない
```

イベントCSVの解析・検証は `src/lib/life-events.ts`、プロフィール設定CSVの解析・検証は `src/lib/life-settings.ts`、性別に応じた平均寿命の算出は `src/lib/life-expectancy.ts` で行う。タイムライン表示は `src/app/components/Timeline.tsx`、性別表示は `src/app/page.tsx` が担当する。読み込み・検証に失敗した場合はサーバー側でエラーを記録し、利用者には詳細を含まない共通メッセージを表示する。

CSVはUTF-8として厳密にデコードし、BOMの混入、列名・列順の不一致、行の列数不一致、許可されていない種別・カテゴリ・状態、必須値の欠落、0〜100以外の年齢を不正として扱う。1行でも不正な場合は全件を表示しない。

プロフィール設定CSVはUTF-8（BOMなし）とし、ヘッダー `current_age,gender` と、0〜100の整数および「男性」「女性」「その他」「未設定」のいずれか、または空の性別欄を1件だけ含める。性別欄が空の場合は「未設定」として扱う。設定CSVの欠落や形式・値の不正は読み込みエラーとして扱い、年齢を既定値へ置き換えない。

## 5. データ項目案

| CSV列 | 要件上の用途 | 設計上の検討 |
| --- | --- | --- |
| `type`（種別） | イベントと目標を区別する | 必須。`event`または`goal` |
| `name`（名称） | 項目の識別・表示 | 必須 |
| `age`（年齢） | 時間軸上の位置 | 必須。整数のみ（0〜100の範囲） |
| `category`（カテゴリ） | 仕事・家族・学業の分類 | 必須。`仕事`・`家族`・`学業`のいずれか |
| `description`（説明） | 項目の補足情報 | 任意。項目選択時に表示 |
| `status`（目標状態） | 目標の進捗 | 目標の場合は必須。「未着手」「進行中」「達成」「中止」のいずれか。イベントでは不要 |

CSV列名と順序はQ2、各列の必須性はQ3、文字コードはQ4、区切り文字はQ5、`type`の値はQ6、`age`の型はQ7、`category`の値はQ19、`status`の値はQ20、CSVの解析方法はQ22・Q24、読み込みと表示の分担はQ23で定める。

プロフィール設定CSVは `data/life-settings.csv` とし、`current_age` 列に年齢、`gender` 列に性別を1件だけ指定する。リポジトリのサンプル値は `29,男性` とし、空の性別欄は「未設定」とする。

## 6. 既存機能との関係

- 共通レイアウトおよびダークモード切替は維持する。
- ダークモードの配色定義を変更せず、新しい画面要素は既存の配色との整合を設計時に確認する。
- 人生可視化で使用しないテンプレート由来のメッセージ表示、メッセージAPI、SQLite連携と、それらに関連するコード・テストを削除する。
- ヘッダーとダークモード機能、およびそれらに関連するコード・テストは維持する。

## 7. 検討事項（一問一答）

以下の質問は一度に一問ずつ確認し、回答後に本書へ記録する。未回答の案は確定設計として扱わない。

### Q1. サンプルCSVのファイル名とリポジトリ内の配置場所をどうしますか？

**回答:** `data/life-events.csv`

### Q2. CSVにどの項目を列として含め、どの順番にしますか？

**回答:** `type, name, age, category, description, status` の順

### Q3. CSVのどの項目を必須にしますか？

**回答:** `type`・`name`・`age`・`category`は必須。`description`は任意。`status`はgoalの場合に必須

### Q4. CSVの文字コードは何にしますか？

**回答:** UTF-8（BOMなし）

### Q5. CSVの区切り文字は何にしますか？

**回答:** カンマ（,）

### Q6. CSVの1行でイベントと目標をどのように区別しますか？

**回答:** `type`列に`event`または`goal`を指定する

### Q7. CSVの年齢は整数だけにしますか、それとも小数も許可しますか？

**回答:** 整数のみ（0〜100の範囲）

### Q8. 年齢の目盛りは何年ごとに表示しますか？

**回答:** 10年ごと

### Q9. イベントと目標を時間軸上でどのように見分けられるようにしますか？

**回答:** イベントは丸、目標はひし形とし、色は変えない

### Q10. 各カテゴリをどのように見分けられるようにしますか？

**回答:** 「仕事」「家族」「学業」の文字ラベルで区別し、色は変えない

### Q11. 未着手・進行中・達成・中止の目標状態をどのように表示しますか？

**回答:** 状態名をテキストで表示し、色は変えない

### Q12. 項目の説明はタイムライン上に常時表示しますか、それとも選択時に表示しますか？

**回答（2026-10-12更新）:** 初期表示ではカードを隠し、マーカーにホバー・キーボードフォーカス・タップしたときに名称・年齢・カテゴリ（目標は状態も）のカードを表示する。説明はマーカーを選択したときに表示する

### Q13. 同じ年齢に複数の項目がある場合、どのように配置しますか？

**回答:** 年齢位置は揃えたまま、縦方向にずらして並べる

### Q14. スマートフォンでは時間軸をどのように閲覧できるようにしますか？

**回答:** 横スクロールで年齢軸全体を閲覧する

### Q15. CSVの読み込みと検証はサーバー側とクライアント側のどちらで行いますか？

**回答:** サーバー側で行う

### Q16. CSVが見つからない、または読み込めない場合のエラー表示をどうしますか？

**回答:** 「サンプルデータを読み込めませんでした」と簡潔に表示し、データは表示しない

### Q17. タイムライン画面で既存ヘッダーのアプリ名とダークモード切替をどう配置しますか？

**回答:** 既存どおりヘッダーの左にアプリ名、右に切替ボタンを配置する

### Q18. 人生可視化で使わないテンプレート由来の機能をどう整理しますか？

**回答:** SQLite・メッセージAPIと関連コード・テストを削除し、ヘッダーとダークモードは維持する

### Q19. CSVのcategory列の値はどう表記しますか？

**回答:** 日本語で`仕事`・`家族`・`学業`

### Q20. CSVのstatus列の値はどう表記しますか？

**回答:** 日本語で`未着手`・`進行中`・`達成`・`中止`

### Q21. 説明を表示するための項目選択をどのように操作しますか？

**回答:** 項目をクリックまたはタップして選択する

### Q22. CSVの解析方法をどうしますか？

**回答:** CSV解析ライブラリを使用する

### Q23. CSV読込・検証とタイムライン表示のコンポーネントをどう分担しますか？

**回答:** CSV読込・検証はサーバー側で行い、検証済みデータを専用のタイムライン表示コンポーネントへ渡す

### Q24. CSV解析に使用するライブラリをどうしますか？

**回答:** `csv-parse`を使用する

### Q25. 登録データ一覧の1ページあたりの表示件数はいくつにしますか？

**回答:** 10件。「前へ」「次へ」でページを移動し、表示範囲と総件数を表示する

### Q26. 登録データ一覧にどの絞り込み条件を設けますか？

**回答:** 種別・カテゴリ・目標状態と、名称・説明のキーワード。複数条件はANDで適用する

### Q27. 登録データ一覧のソート方法はどうしますか？

**回答:** 全列のヘッダーからソートする。初期状態は年齢の昇順とし、別の列を選ぶと昇順、同じ列を再度選ぶと昇順・降順を切り替える。ソート条件を変更したら1ページ目に戻る

### Q28. 現在年齢をどこに設定し、設定が不正な場合はどうしますか？

**回答:** `data/life-settings.csv` に現在年齢と性別を1件保存し、サンプル値を29歳・男性とする。性別欄が空なら「未設定」とし、読み込みできない場合や値が不正な場合はエラーを表示してデータを表示しない

### Q29. 経過した年数をタイムラインでどう表現しますか？

**回答:** 現在年齢までを既存色の濃い線、それ以降を薄い線で示し、境界に「現在」と年齢を表示する

### Q30. 経過済みとこれからのイベント・目標をマーカーでどう区別しますか？

**回答:** 現在年齢以下の項目は塗りつぶし、現在年齢より先の項目は枠線のみで表示する

- 要件定義書に定めた機能・表示範囲を満たす設計となっている。
- 未決定の設計事項は質問と回答が一問一答形式で記録されている。
- ダークモードの既存配色を維持する方法が明確になっている。
- 実装対象と、置き換え・削除対象となるテンプレート機能が明確になっている。
